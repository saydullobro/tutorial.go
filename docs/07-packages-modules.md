# 07. Пакеты, модули и структура проекта

[← Конкурентность](06-concurrency.md) · [К оглавлению](../README.md) · [Дальше: тестирование →](08-testing.md)

## Термины

| Go | Что это | Аналог в Python |
|---|---|---|
| **пакет** (package) | одна папка с `.go`-файлами | модуль / пакет (`import x`) |
| **модуль** (module) | дерево пакетов с общим `go.mod` | проект / дистрибутив на PyPI |
| `go.mod` | имя модуля, версия Go, зависимости | `pyproject.toml` |
| `go.sum` | контрольные суммы зависимостей | хэши в lock-файле |
| кэш модулей (`~/go/pkg/mod`) | общий для всех проектов, версии лежат рядом | `site-packages` в venv |

Виртуальных окружений нет и они не нужны: у каждого проекта в `go.mod`
зафиксированы свои версии, а в общем кэше они не конфликтуют.

## Пакеты

Правила:

- **Одна папка = один пакет.** Все файлы в папке начинаются с одинакового
  `package имя`.
- Файлы одного пакета видят друг друга без импорта — это как один большой файл.
- Имя пакета — короткое, строчными буквами, без подчёркиваний: `user`, `httputil`.
- Аналога `__init__.py` нет.

### Видимость — по регистру первой буквы

```go
package user

// User экспортируется: имя с большой буквы.
type User struct {
	Name  string // поле доступно из других пакетов
	email string // поле доступно только внутри пакета user
}

// New экспортируется.
func New(name, email string) User {
	return User{Name: name, email: normalize(email)}
}

// normalize — приватная функция пакета.
func normalize(s string) string {
	return s
}
```

Никаких `public`/`private`, `_underscore` и `__all__`. Граница приватности —
**пакет**, а не тип: код в том же пакете видит приватные поля чужих структур.

### Импорт

```go
package main

import (
	"fmt"      // стандартная библиотека
	"net/http" // обращаемся по последней части пути: http.Get

	"github.com/google/uuid" // сторонний пакет — полный путь

	"example.com/myapp/internal/user" // свой пакет: имя модуля + путь к папке
)

func main() {
	u := user.New("Аня", "anya@example.com")
	fmt.Println(u.Name, uuid.NewString(), http.StatusOK)
}
```

- Относительных импортов (`from . import x`) нет — всегда полный путь от имени модуля.
- `from x import *` нет: всегда пишется `пакет.Имя`.
- **Циклические импорты запрещены компилятором.** Если `a` импортирует `b`,
  то `b` не может импортировать `a`. Лечится выносом общего в третий пакет
  или интерфейсом.
- Псевдоним: `import str "strings"`. Нужен редко — при конфликте имён.

## Модули и зависимости

```bash
go mod init github.com/username/myapp
```

Имя модуля обычно совпадает с адресом репозитория — по нему другие смогут
сделать `go get`.

Пример `go.mod`:

```text
module github.com/username/myapp

go 1.24

require (
	github.com/google/uuid v1.6.0
	golang.org/x/sync v0.10.0
)
```

Работа с зависимостями:

```bash
go get github.com/google/uuid
```

```bash
go get github.com/google/uuid@v1.6.0
```

```bash
go get -u ./...
```

```bash
go mod tidy
```

| Команда | Действие |
|---|---|
| `go get пакет` | добавить последнюю версию |
| `go get пакет@v1.6.0` | конкретная версия |
| `go get -u ./...` | обновить все зависимости |
| `go mod tidy` | привести `go.mod` и `go.sum` в соответствие с кодом |
| `go list -m all` | показать все зависимости (аналог `pip freeze`) |
| `go mod why пакет` | объяснить, зачем нужна зависимость |

Обычный рабочий процесс: написал `import` в коде → `go mod tidy`.

`go.mod` и `go.sum` коммитятся в репозиторий оба.

Где искать пакеты: <https://pkg.go.dev> — и каталог (аналог PyPI), и
документация для любого публичного модуля.

### Утилиты командной строки

```bash
go install github.com/golangci/golangci-lint/v2/cmd/golangci-lint@latest
```

Бинарник появится в `~/go/bin` — добавь эту папку в `PATH`. Аналог `pipx install`.

## Структура проекта

Официального обязательного шаблона нет. Начинай с простого и усложняй по мере роста.

Маленькая программа:

```text
myapp/
├── go.mod
├── main.go
└── main_test.go
```

Сервис среднего размера:

```text
myapp/
├── go.mod
├── go.sum
├── cmd/
│   ├── server/
│   │   └── main.go        # точка входа: go run ./cmd/server
│   └── migrate/
│       └── main.go        # вторая программа в том же модуле
├── internal/              # код, который нельзя импортировать извне модуля
│   ├── user/
│   │   ├── user.go
│   │   ├── service.go
│   │   └── service_test.go
│   ├── storage/
│   │   └── postgres.go
│   └── httpapi/
│       └── handlers.go
└── README.md
```

- `cmd/<имя>/main.go` — каждая программа в своей папке; в `main` только сборка
  зависимостей и запуск.
- `internal/` — особая папка: компилятор запрещает импортировать её содержимое
  из других модулей. Всё, что не публичная библиотека, клади сюда.
- Тесты лежат **рядом с кодом** в файлах `*_test.go`, отдельной папки `tests/` нет.
- Не создавай пакеты `utils`, `helpers`, `common`, `models` — называй пакет
  по тому, что он **предоставляет**: `user`, `storage`, `auth`.
- Дели по предметным областям (`user`, `order`), а не по слоям
  (`controllers`, `services`, `models`), как это принято в Django.

## Функция init

```go
package config

import "os"

var env string

// init вызывается автоматически один раз при загрузке пакета, до main.
func init() {
	env = os.Getenv("APP_ENV")
	if env == "" {
		env = "dev"
	}
}
```

Используй редко: неявная логика при импорте усложняет тестирование и понимание.
Лучше явная функция `Load()`, вызываемая из `main`.

1. Вынеси тип `Account` из [главы 3](03-structs-methods.md) в пакет
   `internal/bank`, используй его из `cmd/app/main.go`.
2. Убедись, что приватное поле `balance` недоступно из `main`.
3. Подключи `github.com/google/uuid`, сгенерируй ID, посмотри на изменения в `go.mod` и `go.sum`.
4. Создай циклический импорт между двумя пакетами и прочитай ошибку компилятора.
